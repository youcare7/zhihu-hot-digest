## 考点 1：与通用大模型对比（面对“这不就是个套壳 AI 总结？”）

### 1.1 评委刁钻质询（Grill-Me Trap）
> “知乎站内已经有知乎直答，市面上还有 ChatGPT、Kimi、豆包。用户让大模型直接总结一下热榜很难吗？你们做这个简报，本质上难道不是给大模型套了个壳做文本摘要（Summarization）？”

### 1.2 得分点主张（Winning Claim）
- **核心主张**：我们绝不是“又一个平庸的摘要工具”，而是知乎热榜的**“争议分诊台”与“终结争论的决定性拼图定位器”**。
- **机制代差**：通用模型是在“复述各方吵了什么”（信息搬运），读者看完依旧一头雾水；我们直接指出**“这场争论是什么性质、吵不吵得完、缺什么决定性证据才能终结”**。

### 1.3 防御逻辑与心智拆解
1. **普通摘要的无效平滑**：通用大模型默认用“中立和稀泥”的语调生成 500 字，把事实与情绪混为一谈，用户读完陷入“各执一词”的无力感。
2. **争议分诊的分类学价值**：我们通过四分性质（`fact / inference / impression / value`），首创把争论分为“补数据可裁决”与“价值站队无解”。
3. **不可替代的杀手锏**：每一条卡片提炼出「缺的那块拼图」（如：门店直营/加盟财务报表、法定质检报告）。这不仅是总结，更是**指引事实终局的可执行证据检索**。
4. **V3.1 缺口可被当场复核**：光说「缺什么」还是主张，所以我们用知乎「全网搜索」（`GET /api/v1/content/global_search`）为每条缺口补一次站外实证：命中就列出最多 2 条对照信源，未命中就诚实写「全网暂未公开」。评委可以当场点开链接验证我们没有瞎说（双白名单机制见考点 3）。

### 1.4 答辩逐字稿要点（Verbatim Response）
> **（10秒直击）**：“评委老师，这正是我们最想澄清的差异。**普通 AI 摘要只负责复述双方怎么吵，而我们负责告诉你：缺什么关键材料，这场争论才能终结！**”  
> **（30秒展开）**：“请看我们今天的第 5 条热点（开 1300 家无人健身房）。通用模型会总结‘有人支持低成本，有人质疑加盟诈骗’，这是废话；我们的深潜简报直接定性为 `fact`（可裁决的事实之争），并精准锁定「缺的那块拼图」——需要当事方披露直营加盟比、近 12 个月在营名录与单店营收。只要这份数据一出，争论立刻终结。10 分钟内，我们让读者从情绪泥潭直接跃升到事实裁决的高维！”

## 考点 3：大模型幻觉防范（面对“AI 编造假观点、假链接怎么办？”）

### 3.1 评委刁钻质询（Grill-Me Trap）
> “大模型存在严重的幻觉问题，尤其是生成外部引用时经常编造 404 的虚假链接，甚至无中生有编造‘某专家观点’。你们怎么保证简报内容的严肃性与真实性？”

### 3.2 得分点主张（Winning Claim）
- **核心主张**：**“物理隔离素材池 + 编号映射查表 + 候选池白名单隔离”双锁机制**，将大模型与 URL 彻底物理隔离，实测全网假链率为 0.00%；V3.1 的站外核验再叠一层「双白名单」，连站外链接也只认当次搜索的真实返回。

### 3.3 防御逻辑与机制设计
1. **模型绝不接触 URL**：大模型接收的输入只有由搜索 API 真实返回的编号候选摘要（1..10）。大模型仅被允许输出整数编号 `index` 与推荐理由，**严禁输出任何链接字符串**。
2. **后端确定性查表**：大模型返回编号后，后端通过索引字典查表还原出真实知乎链接。
3. **候选池隔离二次拦截**：还原后的 URL 必须通过候选池白名单校验（`allowed = {c.get("Url") for c in candidates}`）。若编号越界或 URL 不在候选池中，立即在后端丢弃该条引用，绝不放行至前端。

### 3.4 答辩逐字稿要点（Verbatim Response）
> **（10秒直击）**：“评委老师，在我们的架构里，**大模型物理上没有机会生成任何假链接！**”  
> **（30秒展开）**：“我们在架构上将‘文本归纳’与‘链接分发’进行了物理切割。大模型只看编号为 1 到 10 的真实候选池，它只准回答‘第 2 号回答很硬核’。真正的知乎 URL 存放在后端的安全内存字典里，由 Python 程序通过编号还原，并与原始搜索候选池白名单（`allowed` 集合）比对校验。V3.1 新增的站外核验沿用同一原则：只认全网搜索当次真实返回的候选，`javascript:` 伪协议、`zhihu.com` 及其子域名、重复链接全部在程序里被拦掉——**前端拿到的每一条 URL，都是上游真的返回过的那一条**。在过去的公网实测中，我们的程序曾精确拦截过大模型输出的越界非法序号，**已交付的数百条延伸阅读中，知乎真实链接成功率保持 100%，假链率为 0！**”

#### V3.1 双白名单（站外核验的第二道池）
1. **第一道池：只认当次返回**。`api_global_search()` 调 `GET /api/v1/content/global_search`（`Filter=host!="zhihu.com"`），返回的 `Items` 就是唯一可信池；`_pick_gap_sources()` 只遍历这个池，兼容 `Url` / `url` 两种键，**不拼接、不补全、不推测**。
2. **第二道闸：协议 + 域名 + 去重 + 上限**。仅放行 `http/https`；剔除 `zhihu.com` 及其子域名（站内材料由延伸阅读负责）；同一 URL 只留一次；最多 2 条（`GAP_VERIFY_MAX_SOURCES = 2`）。
3. **失败即隐身**。429 / 超时 / 结构异常一律 `except Exception` 静默降级为 `skipped`，前端整块不渲染——宁可不显示，也不显示一条没被验证过的信源。
4. **不烧配额**。开关关闭（`ENABLE_GAP_VERIFY=0`）、缺口为空、或命中 `暂无 / 目前无公开可核验材料 / 无需补充材料` 哨兵文案时直接返回 `skipped`，不发起请求。

## 考点 4：成本额度与高并发限流（面对“免费配额那么小，能跑得起来吗？”）

### 4.1 评委刁钻质询（Grill-Me Trap）
> “知乎开放平台每天只给直答 100 次免费配额，搜索也有限制。如果今天有 1000 个人同时访问你的网站，或者知乎直答 API 突发 429 限流，你的服务是不是当场挂掉白屏了？”

### 4.2 得分点主张（Winning Claim）
- **核心主张**：**“单轮生成基线仅 ¥0.41（不含 V3.1 新增的全网核验，该项单轮最多 +10 次且可整层关闭），访客流量与 API 消耗彻底解耦，三层高可用保障零白屏，防劣化棘轮永不把好数据刷坏”**。

### 4.3 防御逻辑与成本模型
1. **Stale-While-Revalidate 天然限流**：
   - 访客访问读取的是当日静态 JSON 缓存（`source=cache`），响应仅需数毫秒。
   - 1000 个并发访问只读缓存，**对知乎 API 的消耗为 0**！
2. **3 小时惰性 TTL 滚动保鲜**：
   - 缓存过期后，由下一次自然访问在后台线程异步拉起刷新，当前用户依然秒开旧缓存，新缓存生成完毕后无缝切换。全天仅触发 5~6 次刷新，直答调用 50~60 次，稳定落在 100 次免费额度安全区（占 50%~60%）。
3. **退避重试与防劣化棘轮（Ratchet）**：
   - 遇 429 内置 30s 固定退避 (RETRY_WAIT=30)；刷新完毕比对条目数，新结果劣于旧缓存立即丢弃，“宁留旧全绿，不覆新残次”。
   - 极端故障自动回落到第三层静态兜底（`source=fallback`），页面永不白屏。
4. **V3.1 全网核验的配额纪律（主动交代，不藏账）**：
   - 每条热点最多触发 1 次全网搜索 → 一轮最多 +10 次；缺口是 `暂无…` 哨兵文案时直接跳过，不发起请求、不消耗配额。
   - 命中与否只决定卡片多一行站外对照，不改变三态裁决；额度紧张时 `ENABLE_GAP_VERIFY=0` 一个环境变量即可整层关闭，自动退回纯站内口径。
   - 因此单轮总调用上限为 1 次热榜 + 10 次站内搜索 + 10 次直答 + 10 次全网搜索，仍被 3 小时 TTL 锁在可控区间。

## 考点 5：三态裁决真实与客观性（面对“定性靠不靠谱？会不会人为制造偏见？”）

> “你们给热榜打上‘真分歧’、‘已共识’、‘待验证’，这种定性是大模型给的，模型本身就有随机性。如果模型误判了，或者模型为了讨好读者硬凑正反两派，岂不是在误导公众？”

### 5.2 得分点主张（Winning Claim）
- **核心主张**：**“严苛的完整性硬闸门 + 不硬造对立的真诚性规则 + 确定性后端统计”**，杜绝黑盒定性与伪民调。

### 5.3 防御逻辑与硬核约束
1. **类型非法即降级**：后端 `sanitize_type` 仅允许 `dispute / consensus / verify`，任何脏值当场降级为最保守的 `verify`。
2. **阵营完整性刚性闸门**：大模型如果声称是“真分歧（dispute）”，但未能成对提取出 2 个成型阵营（标签 $\le 12$ 字、主张 $\le 80$ 字），**后端程序直接将其强制降级为「待验证」**。
3. **已共识条目不留空格**：若全站讨论高度一致（如谴责恶性犯罪），系统如实判定为「已形成共识」，绝不无中生有编造一个反方。
4. **诚实披露局限性**：洞察卡明确标明“仅指本次检索样本中的讨论结构，不代表全站民调”，不搞伪量化。

  ```python
  item_type = sanitize_type(model_output.get("type"))

  # 完整性闸门：说是分歧却凑不出两派 → 降级为待验证，并记日志
  if item_type == TYPE_DISPUTE and not sides:
      item_type = TYPE_VERIFY
      _log(f"  第 {rank} 条声明 dispute 但未给出两个成型阵营，降级为 verify")
  ```
- `scripts/verify_plan_numbers_v2.py`：第 [5] 项硬约束“真分歧且恰好 2 个成型阵营：5/5，非真分歧带阵营：0”。

## 考点 6：团队约束与工程边界（面对“3个大学生怎么保证交付质量？”）

### 6.1 评委刁钻质询（Grill-Me Trap）
> “你们是一个 3 人的大学生团队，在有限时间内做这个项目，功能看起来比较克制，为什么没有做用户注册、个性化推荐、跨平台热榜对比和时间轴演化？”

### 6.2 得分点主张（Winning Claim）
- **核心主张**：**“黑客松最致命的陷阱不是功能太少，而是链路太长、依赖太脆；我们克制聚焦，用确定性工程底座锁定满分边界”**。

### 6.3 防御逻辑与边界哲学
1. **严守功能边界（明确不做什么）**：
   - 不做跨平台抓取：保持对知乎单一社区最深度的信源理解；
   - 不做用户画像与个性化推荐：不制造新的信息茧房；
   - 不堆砌沉重数据库与前端构建：依赖仅一行 `pip install flask`，单实例容器零运维。
2. **把算力与精力砸在核心价值上**：
   - 将精力全力投入到三层高可用、防幻觉双锁、防劣化棘轮与 13/13 自动化回归中，换来全天候 100% 稳定运行。
3. **架构自带演进性（V2 延时摄影）**：
   - 现有的每日缓存（`brief_<日期>.json`）天然构成了历史快照池，V2 仅需加一层历史索引即可无缝长出“72小时时间轴演化追踪”。

### 6.4 答辩逐字稿要点（Verbatim Response）
> **（10秒直击）**：“评委老师，**克制不是能力受限，而是深思熟虑后的战略取舍！**”  
> **（30秒展开）**：“我们观察到黑客松大量作品失败在链路过长、依赖爆炸导致现场翻车。我们 3 个人达成共识：放弃虚幻的花哨功能，把所有力量砸在‘高可用工程底座’与‘知乎生态共生’上。我们做到了依赖仅一行 Flask，内置了 13 项自动化回归脚本和数字自查程序。我们在 V1 把‘当日横切面’打磨到了极致，并且 V1 沉淀的每日快照天然就是未来 V2 演化的燃料。在答辩现场，我们的系统稳如磐石，这就是工程专业度的最好证明！”
